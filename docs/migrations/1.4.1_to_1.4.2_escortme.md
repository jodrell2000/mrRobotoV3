# Migration: 1.4.1 to 1.4.2 - Escortme Feature

**Date**: August 29, 2026

## What's New

### 👋 Escortme Command
A new DJ command allowing automatic removal from the decks after the current song finishes.

#### Usage Examples

**Enable escortme:**
```
!escortme
!escortme stop
```

| Command | Effect | When Applied | Response |
|---------|--------|--------------|----------|
| `!escortme` | Schedule removal after your song ends | When at position 0 (currently playing) or positions 1-20 (queue) | `⏰ Escortme enabled! You'll be removed after your song.` |
| `!escortme` | Error if already enabled | Multiple invocations | `⏰ You already have escortme enabled. Use !escortme stop to cancel.` |
| `!escortme stop` | Cancel scheduled removal | Any time after enabling escortme | `✅ Escortme cancelled. You will remain on the decks.` |
| `!escortme stop` | Error if not enabled | When not previously enabled | `❌ You haven't enabled escortme.` |
| `!escortme` | Error if not on decks | From chat (not DJing) | `❌ You must be on the decks to use the escortme command.` |

#### Room Notification
When a DJ with escortme enabled is automatically removed:
```
👋 {djUsername} had enabled escortme and has left the decks.
```

#### Permission Requirements
- **Role Required**: USER (any room member)
- **Position Required**: DJ at positions 0-20 (must be currently playing or in queue)

## Implementation Details

### How It Works

1. **User Enables**: DJ invokes `!escortme` while on the decks (position 0-20)
   - Flag stored: `{markedAt: timestamp, removeAfterCurrent: boolean}`
   - `removeAfterCurrent: true` if position 0, `false` if in queue

2. **Song Completion**: Handler detects current DJ has escortme enabled
   - Execution: `hangSocketServices.removeDj()` called
   - Notification: Room message posted with 👋 emoji
   - Cleanup: Flag cleared after removal

3. **Escape Paths**: Flags auto-cleared if:
   - DJ manually leaves decks (Phase 4)
   - DJ disconnects from room (Phase 5)
   - Song ends and removal executes (Phase 6)

### Technical Changes

**New Command Handler**:
- File: `src/commands/General Commands/handleEscortmeCommand.js`
- Tests: `tests/commands/handleEscortmeCommand.test.js` (20 tests)

**Modified Handlers**:
- `src/handlers/playedSong.js` - Execute removal on song end
- `src/handlers/removedDj.js` - Clear flag on DJ leave
- `src/handlers/userLeft.js` - Clear flag on room disconnect

**Data Storage**:
- Persistent JSON via `dataService`
- Key: `escortQueue`
- Structure: `{[userUuid]: {markedAt, removeAfterCurrent}}`

## Troubleshooting

### "You must be on the decks to use the escortme command"
- **Cause**: User is not actively DJing (not at position 0-20)
- **Solution**: Join the DJ queue or start playing a song

### "You already have escortme enabled"
- **Cause**: User previously invoked `!escortme` and it's still active
- **Solution**: Use `!escortme stop` first, then re-enable if desired

### "You haven't enabled escortme"
- **Cause**: User invoked `!escortme stop` without previously enabling
- **Solution**: Enable escortme first with `!escortme`

### DJ not removed after song ends
- **Cause**: Could be socket/removal service issue, or flag was cleared
- **Solution**: Check logs for [escortme] messages; verify DJ is still on decks

### Enable works but removal doesn't execute
- **Cause**: DJ may have manually left or disconnected
- **Solution**: Re-enable escortme after rejoining decks

## Performance Impact
- Negligible: Flag operations are simple JSON storage
- Async execution: Removal happens asynchronously after song ends
- No impact on message handling or chat performance

## Known Limitations
- Flag only affects current song; must re-enable for next song
- Position validation is point-in-time (checked at enable, not continuously)
- Limited to positions 0-20 (current queue limit)
- Requires hangSocketServices removal functionality
