# v2.0.0 - Site Independence Architecture

**Release Date**: September 9, 2026

## Overview
This major release introduces a comprehensive architectural refactoring that decouples the bot from the ttfm-socket library through framework specifications, normalized contracts, and pluggable adapters. The foundation is now laid for multi-site support, enabling future integrations with different chat platforms and socket servers without duplicating core bot behavior.

## Major Features

### 🌐 Adapter Pattern Architecture - Multi-Site Foundation
The bot now uses pluggable adapters to abstract external dependencies:

**Socket Adapter Pattern**:
- `AbstractSocketAdapter` - Interface for all socket implementations
- `HangFmSocketAdapter` - Hang.fm implementation (currently the only concrete adapter)
- Single point of coupling: ttfm-socket library imported only in `HangFmSocketAdapter`
- All socket operations route through high-level methods: `connect()`, `disconnect()`, `joinRoom()`, `voteOnSong()`, `removeDj()`, `skipSong()`
- Future adapters (e.g., `TwitchStreamAdapter`, `DiscordSocketAdapter`) can be added without modifying existing code

**API Adapter Pattern**:
- `AbstractSiteAdapter` - Interface for all site API implementations
- `HangFmApiAdapter` - Hang.fm implementation
- Consolidates all REST API calls for user management and authentication
- Methods: `getUserProfile()`, `updateUserNickname()`, `getChatAuthToken()`, `getAllPresentUsers()`, `getGatewayBaseUrl()`, `getAuthHeaders()`
- Future adapters can implement alternative APIs (e.g., Twitch API, Discord API)

**AdapterService Orchestrator**:
- Central service managing adapter initialization and validation
- Validates configuration before allowing bot startup
- Loads appropriate adapters based on framework configuration
- Provides clear error messages for missing/invalid configuration

**ServiceContainer Integration**:
- Adapters registered in serviceContainer during startup (`initializeAdapters()`)
- All services access adapters through `services.socketAdapter` and `services.apiAdapter`
- Adapter initialization is a critical startup gate—bot fails gracefully if adapters can't initialize

### 🔧 Refactored Services

**hangUserService.js**:
- All functions now accept `services` parameter for adapter access
- Functions: `getUserNicknameByUuid()`, `updateHangNickname()`, `getCometChatToken()`, `getAllPresentUsers()`
- Calls `services.apiAdapter` instead of making direct REST calls
- Removes direct imports of config and makeRequest utilities

**hangSocketServices.js**:
- All functions now accept `services` parameter for adapter access
- Functions: `upVote()`, `downVote()`, `removeDj()`, `skipSong()`
- Calls `services.socketAdapter` for all socket operations
- Removes ActionName constants and direct socket.action() calls

**bot.js**:
- Uses `services.socketAdapter` instead of directly importing and using SocketClient
- Event listeners (`statefulMessage`, `statelessMessage`, `serverMessage`, `error`) route through adapter
- Connection status checked via `socketAdapter.isConnected()` instead of raw socket
- Graceful error handling when socket adapter isn't available

### 📋 Configuration

**New Environment Variables**:
- `API_FRAMEWORK` - Specifies which API adapter to load. This must be set explicitly, for example `API_FRAMEWORK=hangfm`.
- `SOCKET_SERVER_URL` - WebSocket server URL (default: 'https://socket.prod.tt.fm')
- `WAVEZFM_API_BASE_URL` - Wavez.fm API base URL for future Wavez adapters.
- `WAVEZFM_ROOM_ID` - Wavez.fm room UUID for future Wavez adapters.
- `WAVEZFM_ROOM_BOT_TOKEN` - Wavez.fm room bot token for future Wavez adapters.

**Wavez.fm Integration Foundation**:
- Added a minimal `wavezfm` framework registration with public chat-related capabilities only.
- Added Wavez API, socket, and messaging adapters for loader validation and initial startup-message delivery.
- Added Wavez message normalization fixtures based on live W0 discovery.
- Wavez public chat send uses the Wavez HTTP room-bot API with dynamic `@wavezfm/api` import from CommonJS.
- Wavez startup skips Hang state validation, CometChat/OpenChat auth, and OpenChat polling for the initial W2 slice.
- Mention formatting is framework-specific: Hang retains `<@uid:...>`, while Wavez uses its `@Name`/`@"Display Name"` syntax.
- Wavez realtime `message_created` packets now enter the normalized command pipeline with startup timestamp, bot-message, and duplicate-ID filtering.
- Wavez command parsing uses the framework-provided `!` prefix rather than assuming the global Hang configuration.
- Wavez realtime reconnects now trigger an HTTP room-state refresh.
- Wavez debug output is framework-aware, and Wavez API failures expose normalized status/code/retryability metadata.
- Initial Wavez room-state normalization now covers room metadata, bot identity, current user, and partial snapshots.
- Wavez startup and reconnect paths now hydrate StateService from the normalized HTTP room snapshot.
- W5 room-state support is complete for verified room metadata, bot identity, current-user context, flexible settings, and partial snapshots.
- W5.5 Wavez chat image handling sends validated public image URLs in message content while preserving Hang image payload behavior.
- W6 Wavez presence and profile capabilities are enabled using the verified room user collection and lazy `client.user.getById()` lookups.
- Initial W7 state support maps verified Wavez queue, playback, and vote fields and adds queue-status reads.
- Queue, moderation, voting, private messages, bot identity updates, and room settings remain explicitly unsupported until later Wavez phases confirm the API behavior.

## Migration Guide
**Existing Hang.fm deployments** should continue to work with their current environment configuration. Developers extending the bot must migrate integrations to the normalized contracts and framework adapters described below:

### Adding a New Platform (e.g., Twitch)
1. Create `src/socketAdapters/TwitchSocketAdapter.js` implementing `AbstractSocketAdapter`
2. Create `src/apiAdapters/TwitchApiAdapter.js` implementing `AbstractSiteAdapter`
3. Register in adapter loaders (socketAdapters/index.js, apiAdapters/index.js)
4. Set `API_FRAMEWORK=twitch` in environment
5. Bot initializes and uses new adapters automatically
